# 모바일 퍼스트 UX 명세

- 상태: 현재 구현 기준선
- 문서 버전: 0.3
- 최종 검토: 2026-07-22

이 문서는 방 코드 기반 2인 주사위 PVP를 모바일 웹에서 먼저 설계하기 위한 화면 구조와 상호작용 계약이다. 게임 단계와 허용 행동은 [게임 규칙 명세](./game-rules.md), 서버 메시지와 복구 방식은 [PVP 아키텍처](./pvp-architecture.md)를 따른다.

## 1. UX 목표

- 세로형 휴대폰 한 화면에서 현재 턴, 현재 주사위, 가능한 행동, 세 라인의 승부를 빠르게 이해한다.
- 같은 라인의 내 보드와 상대 보드가 대응한다는 사실을 시각적으로 드러낸다.
- 한 손 엄지로 핵심 행동을 완료할 수 있게 한다.
- 알까기, 보너스 실드, 타짜, 홀드를 서로 다른 상태와 언어로 표현한다.
- 네트워크가 느리거나 끊겨도 중복 행동과 잘못된 보드 표시를 만들지 않는다.
- 색, 소리, 애니메이션만으로 정보를 전달하지 않는다.

## 2. 기준 화면과 반응형 범위

| 구간 | 기준 | 레이아웃 원칙 |
| --- | --- | --- |
| 최소 휴대폰 | `320 x 568` | 기능 손실 없이 세로 스크롤 허용 |
| 1차 설계 기준 | `360 x 800` | 주요 턴 행동이 첫 화면에 보임 |
| 일반 휴대폰 | `390 x 844` 전후 | 여백과 주사위 크기 확대 |
| 태블릿 | `768px` 이상 | 5개 슬롯 너비를 위해 라인 카드는 세로 유지, 행동 dock은 가로 배치 |
| 넓은 태블릿 | `900px` 이상 | 세 라인 카드를 3열로 배치 |
| 데스크톱 | `1024px` 이상 | 중앙 최대 너비, 모바일 정보 구조 유지 |

- 뷰포트 높이는 `100vh`보다 `100dvh`를 우선해 모바일 주소창 변화에 대응한다.
- 상·하단은 `env(safe-area-inset-*)`를 반영한다.
- 세로 방향을 강제하지 않는다. 가로 방향에서도 모든 행동에 접근할 수 있어야 한다.
- 게임판은 최대 너비를 제한해 큰 화면에서 터치 대상과 시선 이동이 지나치게 벌어지지 않게 한다.
- 브라우저 확대를 막지 않는다.

## 3. 화면 구조

```text
시작
  |- 방 만들기 -> 닉네임 -> 대기방
  `- 방 참가   -> 코드 + 닉네임 -> 대기방

대기방
  -> 두 플레이어 준비
  -> 게임
       |- 일반 턴
       |- 타짜 선택
       |- 보너스 실드 배치
       |- 홀드/항복 확인
       `- 재접속
  -> 결과
       |- 재대결
       `- 방 나가기
```

브라우저 새로고침이나 앱 복귀 때 유효한 좌석 세션과 진행 중인 방이 있으면 시작 화면을 잠깐 보여 주지 않고 복구 화면을 거쳐 현재 대기방·게임·결과 화면으로 이동한다.

## 4. 시작과 방 참가

### 시작 화면

- 서비스명과 한 문장 설명
- 주요 버튼 `방 만들기`
- 보조 버튼 `방 코드로 참가`
- 짧은 규칙 보기 링크
- 원작과 혼동되지 않는 독자적인 이름과 시각 자산

### 닉네임

- 입력창 글자 크기는 최소 16px로 두어 iOS 자동 확대를 피한다.
- 앞뒤 공백을 정규화하고 서버와 같은 길이 정책을 표시한다.
- 닉네임은 로그인이나 좌석 복구 수단이 아니라는 사실을 UI에서 과도하게 설명할 필요는 없지만, 중복 닉네임에 의존하는 흐름은 만들지 않는다.

### 방 코드 입력

- 시각적으로는 6칸처럼 보여도 접근 가능한 단일 입력으로 구현한다.
- 붙여넣기, 소문자 입력, 중간 공백과 하이픈 제거를 지원한다.
- 입력값은 대문자로 정규화한다.
- 존재하지 않음, 만료, 가득 참, 시도 제한을 서로 다른 메시지로 보여 준다.
- 유효한 6자리가 되기 전에는 참가 버튼을 비활성화하지만 서버 검증은 항상 수행한다.

## 5. 대기방

대기방에서 가장 중요한 정보는 공유할 코드와 상대 참가 상태다.

- 방 코드를 큰 고정폭 글꼴로 표시한다.
- `복사`와 지원 환경의 `공유` 버튼을 나란히 제공한다.
- Web Share API를 사용할 수 없으면 복사로 fallback한다.
- 방장과 참가자의 닉네임, 연결 상태, 준비 상태를 표시한다.
- 준비 버튼은 하단 고정 영역에 둔다.
- 두 명이 모두 준비되면 서버 시작 메시지를 기다리고, 클라이언트가 자체적으로 선공을 정하지 않는다.
- 상대를 기다리는 동안에는 방 코드가 화면을 가리지 않는 범위에서 화면 꺼짐 방지 안내나 공유 도움말을 제공할 수 있다.

## 6. 게임 화면 정보 구조

모바일에서는 보드 두 개를 좌우로 축소하지 않는다. 세 개의 **라인 카드**를 세로로 쌓고, 각 카드 안에서 상대 라인과 내 라인을 위아래로 맞춘다. 같은 라인끼리 알까기한다는 관계가 가장 짧은 거리에서 보인다.

```text
┌ 상대 이름 · 연결됨               00:42 ┐
│ 상대 27점              지금 내 차례     │
├─ 1번 라인 ───────────── 상대 우세 +4 ─┤
│ 상대  [ 6 ][ 5 ][   ][   ][   ]    11 │
│ 나    [ 5 ][   ][   ][   ][   ]     5 │
├─ 2번 라인 ───────────── 내가 우세 +3 ─┤
│ 상대  [ 2 ][ 2 ][   ][   ][   ]     6 │
│ 나    [ 5 ][ 4 ][   ][   ][   ]     9 │
├─ 3번 라인 ───────────────── 동률 8 ─┤
│ 상대  [ 3 ][ 5 ][   ][   ][   ]     8 │
│ 나    [ 2 ][ 6 ][   ][   ][   ]     8 │
├─────────────────────────────────────┤
│ 현재 주사위 [ 5 ]  놓을 라인을 선택하세요 │
│ [타짜 · 1회] [아이템 · 2개]      [홀드] │
└──────────── 하단 safe area ────────────┘
```

실제 시각 디자인은 달라질 수 있지만 정보 우선순위는 유지한다.

1. 누구의 턴인지와 남은 시간
2. 현재 또는 보너스 주사위
3. 지금 가능한 대상
4. 각 라인의 점수와 우세
5. 타짜 사용권, 인벤토리 수량, 홀드, 메뉴
6. 전체 행동 기록

### 라인 카드

- 모바일에서는 3개를 세로로, 넓은 화면에서는 3열로 배치한다.
- 각 카드에 라인 이름, 상대 슬롯 5개, 내 슬롯 5개, 양쪽 점수를 함께 둔다.
- `상대 우세`, `내 우세`, `동률`을 색뿐 아니라 텍스트나 아이콘으로 표시한다.
- 주사위 슬롯의 물리적 위치는 규칙상 의미가 없으므로 카드 전체 행을 행동 대상으로 사용한다.
- 빈 슬롯을 보이게 하되, 사용자는 빈 슬롯 하나가 아니라 라인을 선택한다.
- 실드는 테두리와 방패 아이콘, 보조 텍스트를 함께 사용한다.

### 상단 상태 영역

- 상대 닉네임과 연결 상태
- 현재 턴 주체
- 서버 deadline 기준 카운트다운
- 양쪽 총점
- 방 코드, 음향, 규칙, 항복은 overflow 메뉴에 배치

상대가 홀드했다면 닉네임 옆에 `홀드` 배지를 계속 표시한다. 누군가 15칸을 채우면 턴 건너뛰기 없이 즉시 종료 전환을 시작한다.

### 하단 행동 dock

- 현재 주사위를 가장 크게 보여 준다.
- 한 문장 지시를 함께 표시한다.
- 타짜, 인벤토리, 홀드 같은 현재 단계의 보조 행동을 제공한다.
- `padding-bottom`에 하단 safe area를 더한다.
- 키보드가 필요 없는 게임 화면에서는 dock이 항상 엄지 범위에 남는다.
- 보드가 길어져 스크롤될 때 마지막 라인 카드가 dock 아래에 가려지지 않도록 같은 높이의 하단 여백을 둔다.

## 7. 게임 단계별 상호작용

| 서버 단계 | 화면 상태 | 활성 대상 |
| --- | --- | --- |
| 상대 턴 | 읽기 전용, 상대 턴과 타이머 표시 | 규칙/메뉴/항복 |
| `TURN_ACTION` | 현재 주사위와 행동 안내 | 합법인 내 배치 라인, 알까기 라인, 타짜, 인벤토리, 홀드 |
| 아이템 대상 선택 | 행 단위 행동을 잠시 숨기고 선택 순서 안내 | 교환 가능한 내/상대 주사위 또는 변환 가능한 양쪽 주사위 |
| `TAZZA_CHOICE` | 원래 눈과 새 눈 선택 sheet | 두 후보, 홀드, 항복 |
| `BONUS_PLACEMENT` | 실드 주사위와 점수 귀속 안내 | 양쪽 보드의 빈 라인 |
| 명령 전송 중 | 누른 대상 pending 표시 | 추가 게임 입력 잠금 |
| 연결 복구 중 | 보드 위 복구 overlay | 게임 입력 없음 |
| `FINISHED` 직후 | 기존 보드 위에 2초간 `게임 종료` overlay | 추가 입력 없음 |
| `FINISHED` 전환 완료 | 결과 화면 | 재대결, 나가기 |

클라이언트가 합법 행동을 추론해도 되지만, 하이라이트의 기준은 가능하면 서버 스냅샷의 `legalActions`를 사용한다.

## 8. 일반 배치와 알까기

### 대상 구분

- 내 행의 합법 라인에는 `놓기` 라벨과 차분한 강조색을 사용한다.
- 상대 행의 공격 가능한 라인에는 `알까기` 라벨, 제거될 일반 주사위 표시, 공격 아이콘을 사용한다.
- 같은 눈 실드는 제거 대상 표시에서 제외한다.
- 내 같은 라인이 가득 차 공격할 수 없으면 상대에게 같은 눈이 있어도 공격 하이라이트를 보여 주지 않는다.
- 색맹 사용자를 위해 테두리 형태, 아이콘, 텍스트를 함께 바꾼다.

### 탭 처리

- 합법 라인 전체를 최소 48px 높이의 탭 대상으로 만든다.
- 일반 배치와 알까기는 한 번 탭하면 즉시 명령을 전송한다.
- 전송 즉시 눌림·로딩 피드백을 보이되, 서버 승인 전에는 보드에 주사위를 확정 배치하거나 제거하지 않는다.
- 응답을 기다리는 동안 다른 게임 행동을 잠근다.
- 응답이 유실되면 새 `actionId`를 만들지 않고 같은 명령을 재전송한다.

### 알까기 연출

서버 이벤트 순서를 사용해 다음처럼 보여 준다.

1. 입력 잠금과 공격 대상 강조
2. 공격 주사위 소모
3. 상대의 동일 눈 일반 주사위 전부 제거
4. 변경된 라인 점수 표시
5. 보너스 실드 굴림 결과 표시
6. `BONUS_PLACEMENT` 안내로 전환

연출 중에도 서버 스냅샷은 이미 확정된 상태다. 탭을 막기 위해 애니메이션 완료를 서버 판정 조건으로 쓰지 않는다.

## 9. 보너스 실드 배치

보너스 단계는 일반 턴과 시각적으로 확실히 달라야 한다.

- 현재 주사위에 방패 아이콘과 `보너스 실드`를 표시한다.
- 안내 문구는 `실드를 놓을 보드를 선택하세요`처럼 대상이 양쪽임을 드러낸다.
- 양쪽 보드의 빈 라인을 모두 강조한다.
- 상대 보드에 놓으면 상대 점수가 된다는 내용을 상대 대상 근처에 짧게 표시한다.
- 높은 눈을 상대에게 실수로 주는 것을 막기 위해 탭 전 hover에 의존하지 않는다. 선택 대상에 `상대에게 놓기`가 항상 보이게 한다.
- 보너스 단계에는 타짜와 홀드 버튼을 숨기거나 비활성화하고 이유를 접근 가능한 설명으로 제공한다.
- 배치가 완료되면 서버 이벤트에 따라 점수를 갱신하고 다음 턴으로 전환한다.

보너스 배치 시간 만료 시 서버가 방금 공격한 상대 라인에 자동 배치한다. 카운트다운 마지막 구간에 `시간이 끝나면 공격한 라인에 자동 배치됩니다`를 표시한다.

## 10. 타짜의 손놀림

- 사용 전 버튼에 `경기당 1회` 또는 남은 횟수 `1`을 표시한다.
- 사용 불가 상태를 단순히 회색으로만 만들지 않고 `사용 완료`, `보너스 실드에는 사용 불가` 같은 이유를 제공한다.
- 사용을 누르면 먼저 서버가 후보를 생성할 때까지 짧은 pending 상태를 보인다.
- 후보가 도착하면 하단 sheet에서 두 주사위를 같은 크기로 나란히 보여 준다.
- 각각 `기존`, `새 주사위` 라벨을 붙인다.
- 시작 실드라면 두 후보 모두 방패 표시를 유지한다.
- 후보 카드를 탭하면 바로 `CHOOSE_TAZZA_DIE`를 전송하고 중복 입력을 잠근다.
- sheet를 브라우저 뒤로가기로 닫아 선택 단계를 숨기지 않는다. 뒤로가기는 확인 후 홀드 또는 게임 복귀로 처리한다.
- 상대 화면에는 후보 눈을 노출하지 않고 `상대가 주사위를 고르는 중`만 표시한다.

## 11. 인벤토리와 아이템 선택

- 행동 dock의 `아이템` 버튼에는 남은 총수량을 표시하고, sheet 안에서는 아이템별 수량과 효과를 보여 준다.
- sheet 상단에 `한 턴 최대 1개`, `사용 후에도 착수 가능`을 명시한다.
- 사용 완료, 수량 소진, 합법 대상 없음은 각 아이템 버튼의 비활성 상태와 설명으로 구분한다.
- 아이템 선택 중에는 일반 배치·알까기 행 버튼을 숨겨 주사위 직접 선택과 충돌하지 않게 한다.
- 서버 응답을 기다리는 동안 다른 주사위와 아이템 입력을 잠근다. 승인 전에는 눈이나 보드 위치를 낙관적으로 바꾸지 않는다.

### 라인 교환

1. 인벤토리에서 `라인 교환`을 선택한다.
2. 교환 가능한 라인의 내 주사위를 모두 강조하고 `먼저 교환할 내 주사위를 선택하세요`라고 안내한다.
3. 내 주사위를 고르면 같은 라인의 상대 주사위만 강조한다.
4. 상대 주사위를 고르는 즉시 하나의 `USE_SWAP_ITEM` 명령을 보낸다.
5. 선택 중 언제든 `아이템 선택 취소`로 현재 주사위 행동 화면에 돌아갈 수 있다.

### 눈 변환

1. 인벤토리에서 `눈 변환`을 선택한다.
2. 내 보드와 상대 보드의 모든 합법 주사위를 같은 선택 스타일로 강조한다.
3. 주사위 하나를 고르는 즉시 `USE_REROLL_ITEM`을 보낸다.
4. 승인 이벤트에 이전 눈과 새 눈을 함께 표시하고, 실드 표시는 그대로 유지한다.

아이템 승인 뒤 대상 선택 모드는 닫히고 일반 `TURN_ACTION` 화면으로 돌아간다. 사용자는 남아 있는 현재 주사위를 놓거나 알까기·타짜·홀드를 이어서 선택할 수 있다.

## 12. 홀드와 항복

두 행동은 결과가 다르므로 위치, 문구, 확인 강도를 분리한다.

### 홀드

- 일반 행동 dock에 보조 버튼으로 보여 전략 행동임을 알 수 있게 한다.
- 탭하면 확인 sheet를 연다.
- 제목: `남은 턴을 모두 포기할까요?`
- 설명: `현재 주사위를 버리고 이번 경기에서 더 이상 턴을 받지 않습니다. 지금까지의 보드 점수로 승부는 계속됩니다.`
- 확인: `홀드하기`
- 취소: `계속 플레이`
- 확인 버튼은 일반 주요 버튼과 형태를 달리하되 항복만큼 위험하게 표현하지 않는다.

### 항복

- 상단 overflow 메뉴 안에 둔다.
- 탭하면 별도의 강한 확인 sheet를 연다.
- 제목: `경기를 포기할까요?`
- 설명: `즉시 패배로 처리되며 되돌릴 수 없습니다.`
- 확인: `항복하기`
- 취소: `취소`
- 확인 버튼은 위험 색상과 텍스트를 함께 사용한다.

브라우저 뒤로가기, 새로고침, 탭 닫기를 곧바로 항복으로 해석하지 않는다. 재접속 유예를 먼저 적용한다.

## 13. 턴과 타이머

- `내 차례`, `상대 차례`, `상대가 홀드해 연속 진행`을 구분해 표시한다.
- 카운트다운은 서버의 절대 `deadlineAt`으로 매초 다시 계산한다.
- 브라우저 탭이 백그라운드에 있다 돌아오면 누적 decrement를 신뢰하지 않고 서버 시각과 재동기화한다.
- 10초 이하에서는 색만 바꾸지 않고 숫자, 진동/소리 선택 설정, 텍스트로 함께 알린다.
- 소리와 진동은 기본 규칙 이해에 필수적이지 않아야 한다.
- 시간 만료 뒤 클라이언트가 자체 홀드하지 않고 서버의 시스템 행동 이벤트를 기다린다.

## 14. 네트워크와 복구 UX

### 내 연결이 불안정할 때

- heartbeat 지연 시 상단에 `연결이 불안정합니다`를 표시한다.
- 소켓이 끊기면 게임 입력을 막는 `다시 연결하는 중` overlay를 연다.
- 자동 재접속에는 지수 backoff와 작은 jitter를 사용하되 서버 유예 시간 안에서 계속 시도한다.
- 복구되면 진행 중 애니메이션과 로컬 임시 상태를 취소하고 전체 서버 스냅샷으로 교체한다.
- 같은 `actionId`의 승인 결과가 복구 스냅샷에 반영돼 있으면 애니메이션을 두 번 재생하지 않는다.

### 상대 연결이 끊겼을 때

- 보드를 지우거나 결과 화면으로 가지 않는다.
- `상대가 재접속 중입니다`와 서버 유예 시간을 표시한다.
- 내 행동 입력은 서버 정책에 따라 잠그고, 클라이언트가 임의로 턴을 넘기지 않는다.
- 상대가 돌아오면 `상대가 돌아왔습니다`를 짧게 알리고 서버 상태로 재개한다.
- 유예가 끝나면 `연결 끊김으로 승리` 결과를 서버에서 받는다.

### 오류 표시

- `STALE_VERSION`: toast보다 최신 스냅샷 복구를 우선하고 `최신 게임 상태로 갱신했습니다`를 알린다.
- `NOT_YOUR_TURN` / `INVALID_PHASE`: 오래된 화면을 갱신하고 현재 턴을 강조한다.
- `ALKKAGI_NOT_AVAILABLE` / `LANE_FULL`: 해당 하이라이트를 제거하고 짧은 이유를 보여 준다.
- `RATE_LIMITED`: 재시도 가능 시각을 안내한다.
- 알 수 없는 오류: 행동을 추정 재적용하지 말고 복구 버튼과 진단 ID를 제공한다.

## 15. 결과 화면

결과는 승패 감정과 판정 근거를 함께 보여 준다.

- 서버가 `FINISHED`를 확정하면 추가 입력을 즉시 막는다.
- 마지막으로 확정된 보드는 그대로 유지하고 화면 위에 `게임 종료`와 `최종 결과를 확인합니다` overlay를 2초간 표시한다.
- 2초 뒤 결과 화면으로 전환한다. 이 지연은 클라이언트 연출이며 서버의 종료 확정이나 명령 차단을 늦추지 않는다.
- 새로고침이나 재접속으로 이미 종료된 경기에 들어온 경우에도 같은 짧은 전환 뒤 결과를 표시한다.

- `승리`, `패배`, `무승부`를 최상단에 표시한다.
- 정상 종료, 항복, 연결 끊김 패배를 별도 이유로 표시한다.
- 세 라인의 양쪽 점수, 승리 라인 수, 총점을 비교한다.
- 총점 판정이 사용됐다면 `라인 승수가 같아 총점으로 결정`을 설명한다.
- 총점까지 같으면 `총점도 같아 무승부`를 설명한다.
- 항복·연결 끊김 종료는 점수표를 참고 정보로만 표시하고 승패 근거처럼 보이게 하지 않는다.
- 주요 버튼 `재대결 요청`
- 보조 버튼 `방 나가기`
- 상대의 재대결 응답을 기다릴 때 요청 취소 또는 나가기 경로를 제공한다.

재대결이 시작되면 이전 결과 화면의 상태를 재사용하지 않고 새 `gameId`의 초기 스냅샷으로 전환한다.

## 16. 접근성

### 터치와 키보드

- 주요 터치 대상은 최소 `48 x 48px`를 권장한다.
- 인접한 위험 행동 사이에 충분한 간격을 둔다.
- 모든 행동은 키보드와 switch 입력으로도 수행할 수 있어야 한다.
- focus 순서는 상단 상태 -> 라인 1..3 -> 현재 주사위 -> 행동 순으로 예측 가능하게 둔다.
- sheet가 열리면 focus를 안으로 이동하고 닫을 때 실행 버튼으로 돌린다.

### 시각

- 주사위 핍만 보여 주지 않고 접근성 이름에 `일반 주사위 5`, `실드 주사위 2`처럼 숫자와 종류를 넣는다.
- 실드, 공격 가능, 우세, 연결 상태를 색 이외의 테두리·아이콘·텍스트로도 표시한다.
- 본문과 컨트롤은 WCAG AA 대비를 목표로 한다.
- 200% 확대와 큰 글자에서도 게임 행동이 잘리거나 겹치지 않아야 한다.
- 텍스트를 이미지 안에 굽지 않는다.

### 알림과 움직임

- 턴 시작, 주사위 결과, 제거 결과, 점수 변화, 오류를 적절한 `aria-live` 영역에 짧게 알린다.
- 여러 제거 이벤트를 하나씩 장황하게 읽지 않고 `상대 1번 라인의 일반 5 두 개를 제거했습니다`처럼 묶는다.
- `prefers-reduced-motion`에서는 주사위 회전과 이동을 짧은 fade/상태 교체로 바꾼다.
- 소리 없이도 모든 상태를 이해할 수 있게 하고, 효과음은 사용자 설정으로 끌 수 있게 한다.

## 17. 클라이언트 상태 처리 원칙

클라이언트는 서버 스냅샷과 UI 연출 상태를 분리한다.

```text
authoritativeGameState  서버가 보낸 최신 게임 상태
inFlightAction          아직 응답을 기다리는 actionId와 명령
animationQueue          서버 이벤트에서 만든 일시적 연출
connectionState         CONNECTED | UNSTABLE | RECONNECTING
```

- 누른 즉시 보드를 낙관적으로 변경하지 않는다.
- 대신 100ms 안에 눌림, spinner, 대상 잠금 같은 로컬 피드백을 보인다.
- 승인 이벤트가 오면 애니메이션을 재생하고 최종 스냅샷과 일치시킨다.
- 거절되면 보드 rollback을 만들지 않고 서버 스냅샷을 그대로 유지한다.
- 컴포넌트별 로컬 복사본이 아니라 하나의 게임 스냅샷을 기준으로 그린다.
- 페이지 복원 캐시에서 돌아올 때 소켓과 버전을 다시 확인한다.

## 18. 성능과 자산

- 주사위는 독자적인 CSS/SVG 자산으로 제작해 해상도와 대비를 유지한다.
- 첫 게임 진입에 필요하지 않은 규칙 상세, 결과 공유 기능, 무거운 효과는 지연 로드한다.
- 폰트와 이미지 크기를 제한하고 게임 화면에서 layout shift가 생기지 않게 슬롯 크기를 예약한다.
- 느린 기기에서도 입력 잠금과 서버 응답 표시는 애니메이션보다 우선한다.
- 장식 효과가 네트워크 상태나 현재 턴 표시를 가리지 않게 한다.

## 19. 분석 이벤트의 최소 범위

개인정보나 세션 값을 보내지 않고 UX 개선에 필요한 사건만 수집한다.

- 방 생성·참가 성공/실패 분류
- 준비부터 게임 시작까지 걸린 시간
- 행동별 선택 수와 서버 거절 code
- 타짜, 아이템 종류, 홀드, 항복 사용 시점
- 재접속 시도와 성공
- 결과 화면의 재대결 요청
- 기기 구간과 reduced-motion 사용 여부

`roomCode`, `sessionToken`, 닉네임, 주사위 전체 로그는 일반 제품 분석 payload에 넣지 않는다. 게임 감사 로그는 서버 운영 로그로 분리한다.

- [ ] 빠른 더블 탭에서 같은 행동이 한 번만 보임

- [ ] 눈 변환에서 내 주사위와 상대 주사위 모두 선택 가능하며 실드 종류 유지
- [ ] 한 턴 두 번째 아이템 비활성화와 아이템 사용 뒤 일반 착수 가능
- [ ] 홀드와 항복 확인 문구·결과가 서로 다름
- [ ] 상대 홀드 후 내 연속 턴 표시
- [ ] 어느 한쪽이 15번째 일반 주사위 또는 보너스 실드를 배치하면 다음 턴 없이 종료
- [ ] `게임 종료` overlay가 2초간 보인 뒤 결과 화면으로 전환
- [ ] 라인 승수 동률 뒤 총점 판정과 최종 무승부 설명
- [ ] 200% 확대, 키보드 전용, VoiceOver/TalkBack 기본 흐름
- [ ] 색각 시뮬레이션에서도 실드·공격·우세 구분
- [ ] reduced-motion에서 모든 상태 변화 인지 가능
- [ ] 네트워크 지연·패킷 유실 뒤 최신 서버 스냅샷과 일치
