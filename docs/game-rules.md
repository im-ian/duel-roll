# 게임 규칙 명세

- 상태: 현재 구현 기준선
- 문서 버전: 0.7
- 최종 검토: 2026-07-27

이 문서는 방 코드 기반 2인 PVP에서 서버와 모든 클라이언트가 같은 결과를 계산하기 위한 규범적 규칙이다. 원작에서 확인된 동작과 웹 PVP를 위해 정한 정책을 구분한다.

## 1. 범위와 용어

한 게임에는 `PLAYER_A`, `PLAYER_B` 두 좌석이 있다. 좌석은 서버 데이터에서 고정하며, 화면에서 어느 쪽에 보이는지와 무관하다.

각 플레이어의 보드는 다음으로 구성된다.

- `lane 0`, `lane 1`, `lane 2`의 세 라인
- 라인마다 최대 다섯 개의 주사위
- 총 열다섯 칸

UI에서는 라인을 상단·중단·하단으로 표시할 수 있다. 알까기의 “같은 라인”은 항상 동일한 서버 라인 인덱스를 뜻한다. 모바일에서 상대 보드를 위, 내 보드를 아래에 놓거나 데스크톱에서 좌우로 놓아도 이 대응 관계는 바뀌지 않는다.

주사위는 다음 속성을 가진다.

```text
Die
- id: 게임 안에서 유일한 식별자
- face: 1 | 2 | 3 | 4 | 5 | 6
- kind: NORMAL | SHIELD
- createdBy: 주사위를 생성한 행동의 플레이어
```

주사위가 어느 플레이어의 점수에 포함되는지는 `createdBy`가 아니라 현재 놓인 보드로 결정한다. 내가 알까기로 얻은 실드를 상대 보드에 놓으면 상대 점수다.

## 2. 게임 시작

**원작 확인**

1. 두 플레이어가 준비하면 서버가 선공을 무작위로 정한다.
2. 선공의 첫 번째 주사위만 `SHIELD`다.
3. 최초 실드는 선공 자신의 보드에만 놓을 수 있다.
4. 최초 실드에도 타짜의 손놀림을 사용할 수 있다. 어느 눈을 고르더라도 `SHIELD` 속성은 유지된다.
5. 이후 일반 턴에 굴리는 주사위는 `NORMAL`이다. 알까기 보너스로 굴리는 주사위만 별도로 `SHIELD`가 된다.

서버는 선공 결정과 주사위 생성을 모두 담당해야 한다.

**프로젝트 확장 규칙**

일반 턴 주사위는 실드 강화 아이템을 사용하면 눈을 유지한 채 `SHIELD`가 될 수 있다.

## 3. 점수

**원작 확인**

같은 라인에서 눈 `v`가 `c`개라면 해당 눈 그룹의 점수는 다음과 같다.

```text
groupScore(v, c) = v × (2c - 1), c > 0
lineScore = 각 눈 그룹 점수의 합
```

따라서 한 개는 액면가, 같은 눈 두 개는 액면가의 3배, 세 개는 5배, 네 개는 7배, 다섯 개는 9배다.

| 라인 | 계산 | 점수 |
| --- | --- | ---: |
| `5` | `5` | 5 |
| `5, 5` | `5 × 3` | 15 |
| `5, 5, 5` | `5 × 5` | 25 |
| `5, 5, 2` | `(5 × 3) + 2` | 17 |
| `4, 4, 2` | `(4 × 3) + 2` | 14 |
| `6, 6, 6` | `6 × 5` | 30 |
| `5, 5, 5, 5, 5` | `5 × 9` | 45 |

`SHIELD`도 점수와 같은 눈 개수 계산에서는 `NORMAL`과 동일하며 알까기로 제거되지 않는다.

**프로젝트 확장 규칙**

실드는 주사위 교환·눈 변환·주사위 파괴·주사위 리롤·홀수·짝수 아이템과 맵 효과의 대상이 되지 않는다. 이 추가 보호 규칙은 시작 실드, 알까기 보너스 실드, 아이템으로 강화한 실드에 동일하게 적용한다.

점수는 저장된 별도 진실값으로 취급하지 않는다. 서버는 보드의 주사위로부터 계산한 값을 스냅샷에 제공한다. 클라이언트가 표시 편의를 위해 같은 순수 함수를 공유하더라도 최종 판정에는 서버 값을 사용한다.

## 4. 턴과 행동 가능 여부

플레이어가 다음 두 조건을 모두 만족하면 행동 가능하다.

```text
eligible(player) = !player.held && player.board에 빈칸이 있음
```

턴 시작 시 서버가 주사위를 굴리고 해당 플레이어의 입력을 기다린다. 일반 입력 단계에서 가능한 행동은 다음과 같다.

- 자신의 빈 라인에 현재 주사위 배치
- 조건을 만족하는 상대 라인에 알까기
- 아직 사용하지 않았다면 타짜의 손놀림 사용
- 이번 턴에 아직 아이템을 사용하지 않았다면 인벤토리 아이템 하나 사용
- 홀드
- 항복

행동이 턴을 끝내면 우선 상대 플레이어부터 다음 행동 가능자를 찾는다. 상대가 행동 불가능하고 방금 행동한 플레이어는 가능하다면 같은 플레이어가 연속 턴을 얻는다. 둘 다 행동 불가능하면 게임을 종료한다.

어느 플레이어든 보드의 15칸을 먼저 채우면 다음 턴을 만들지 않고 즉시 현재 보드로 승패를 판정한다. 선공·후공이나 15번째 주사위를 만든 행동의 종류와 무관하며, 15칸을 채운 플레이어가 자동으로 승리하는 것은 아니다.

## 5. 일반 배치

**원작 확인**

- `NORMAL` 주사위는 현재 플레이어 자신의 보드에만 놓을 수 있다.
- 선택한 라인에 빈칸이 하나 이상 있어야 한다.
- 라인 안에서 어느 슬롯을 먼저 채우는지는 게임 결과에 영향을 주지 않는다. 서버는 일관된 순서로 빈 슬롯을 채운다.
- 배치가 확정되면 현재 주사위가 보드로 이동하고 턴이 끝난다.

최초 실드는 일반 배치와 같은 흐름을 사용하지만 대상은 선공 자신의 보드로 제한한다.

## 6. 알까기

### 6.1 실행 조건

**원작 확인**

현재 주사위의 눈이 `v`, 선택한 라인이 `L`일 때 다음 조건을 모두 만족해야 한다.

1. 현재 주사위가 `NORMAL`이다.
2. 내 `L` 라인에 빈칸이 있다.
3. 상대 `L` 라인에 눈이 `v`인 `NORMAL` 주사위가 하나 이상 있다.

같은 눈이 여러 라인에 있다면 조건을 만족하는 라인 중 하나를 플레이어가 선택한다. 내 대응 라인이 가득 찼다면 공격 주사위가 결과적으로 사라지더라도 그 라인에는 알까기할 수 없다.

### 6.2 처리 순서

**원작 확인**

1. 공격에 사용한 현재 주사위를 소모한다. 내 보드에는 남지 않는다.
2. 상대의 선택 라인에서 같은 눈의 `NORMAL` 주사위를 모두 제거한다.
3. 같은 눈의 `SHIELD` 주사위는 제거하지 않는다.
4. 서버가 1~6 중 하나를 새로 굴린다.
5. 새 주사위를 `SHIELD`로 만들고 보너스 배치 단계로 전환한다.
6. 공격자가 자기 또는 상대 보드의 빈 라인 하나를 선택해 보너스 실드를 놓는다.
7. 배치가 끝나면 턴을 종료한다.

알까기 명령의 주사위 소모, 상대 주사위 제거, 보너스 실드 생성은 하나의 서버 트랜잭션으로 처리한다. 보너스 실드의 최종 배치는 다음 명령으로 받더라도 중간 상태가 유실되어서는 안 된다.

### 6.3 보너스 실드 제한

- 보너스 실드는 어느 플레이어의 어느 빈 라인에도 놓을 수 있다.
- 상대 보드에 놓으면 상대 점수와 같은 눈 보너스에 포함된다.
- 보너스 실드 자체는 알까기를 연쇄 발동하지 않는다.
- 보너스 실드에는 타짜의 손놀림을 사용할 수 없다.
- 보너스 실드를 놓기 전에는 일반 턴으로 넘어갈 수 없다.

## 7. 타짜의 손놀림

**원작 확인**

- 플레이어마다 게임당 한 번 사용할 수 있다.
- 현재 눈을 보존한 채 대체 눈 하나를 서버가 추가로 생성한다.
- 플레이어는 기존 눈과 대체 눈 중 하나를 선택한다.
- 선택한 눈은 원래 주사위의 종류를 유지한다. 최초 실드에서 사용했다면 선택 결과도 실드다.
- 선택 후에는 일반 배치 또는 알까기를 계속 진행한다.
- 알까기로 얻은 보너스 실드에는 사용할 수 없다.

**PVP 규칙 — 추후 원작 검증 가능**

대체 눈은 기존 눈을 제외한 나머지 다섯 눈 중 균등하게 선택한다. 커뮤니티 플레이 분석과 관찰을 따른 결정이며, 규칙 엔진에서는 RNG 정책을 주입할 수 있게 만들어 나중에 독립적인 d6 재굴림으로 바꾸더라도 상태 구조가 달라지지 않게 한다.

타짜를 실행한 순간 사용권은 소모된다. 선택 단계에서 홀드하면 두 후보를 모두 버리고 사용권도 복구하지 않는다. 두 후보는 두 개의 실제 주사위가 아니며, 선택된 하나만 이후 행동에 사용된다.

## 8. 인벤토리와 아이템

**프로젝트 확장 규칙**

아이템만 빠르게 확인하려면 [아이템 명세](./items.md)를 참고한다. 이 절은 아이템 합법성에 대한 최종 규칙이다.

원작 고증에 묶이지 않는 전략 요소로 다음 아이템 카탈로그를 둔다. 카탈로그 등록과 기본 지급은 별도 정책이며, 현재는 실드 강화·주사위 파괴·홀수·짝수 주사위 네 종류를 하나씩 지급한다.

| 아이템 | 현재 시작 수량 | 효과 |
| --- | ---: | --- |
| 주사위 교환 (`SWAP`) | 0 | 같은 라인에 놓인 내 주사위 하나와 상대 주사위 하나를 1:1 교환 |
| 눈 변환 (`REROLL`) | 0 | 양쪽 보드에 놓인 주사위 하나를 기존 눈과 다른 무작위 눈으로 변경 |
| 실드 강화 (`SHIELD`) | 1 | 현재 일반 턴 주사위의 눈과 ID를 유지한 채 `SHIELD`로 변경 |
| 무작위 투하 (`DROP`, 가칭) | 0 | 양쪽 보드의 무작위 빈칸에 무작위 일반 주사위를 하나씩 추가 |
| 주사위 파괴 (`DESTROY`) | 1 | 양쪽 보드에 놓인 일반 주사위 하나를 선택해 제거 |
| 주사위 리롤 (`TURN_REROLL`) | 0 | 현재 일반 턴 주사위를 기존 눈과 다른 무작위 눈으로 다시 굴림 |
| 홀수 주사위 (`ODD`) | 1 | 현재 일반 턴 주사위를 기존 눈과 다른 무작위 홀수 눈으로 변경 |
| 짝수 주사위 (`EVEN`) | 1 | 현재 일반 턴 주사위를 기존 눈과 다른 무작위 짝수 눈으로 변경 |

아이템에는 다음 공통 규칙을 적용한다.

- 현재 플레이어의 `TURN_ACTION`에서만 사용할 수 있다.
- 한 턴에는 종류와 무관하게 최대 하나만 사용할 수 있다.
- 사용권은 명령이 성공한 순간 인벤토리에서 차감한다.
- 아이템 사용은 원칙적으로 턴을 끝내지 않고 현재 pending 주사위도 소모하지 않는다. 단, 무작위 투하로 어느 보드가 15칸을 채우면 양쪽 투하를 모두 해결한 뒤 즉시 경기를 종료한다.
- 사용 후에도 일반 배치, 알까기, 타짜, 홀드를 이어서 선택할 수 있다.
- 타짜 선택을 끝내 다시 `TURN_ACTION`으로 돌아온 뒤에도, 그 턴에 아이템을 아직 쓰지 않았다면 사용할 수 있다.
- `TAZZA_CHOICE`, `BONUS_PLACEMENT`, 상대 턴, 종료된 경기에서는 사용할 수 없다.
- 다음 턴이 시작될 때 `itemUsedThisTurn`을 초기화한다. 같은 플레이어가 연속 턴을 받아도 새 턴이면 다시 사용할 수 있다.

모든 `SHIELD` 주사위는 `isDieEffectImmune` 보호 판정을 공유한다. 현재 구현된 아이템은 이 판정을 서버 명령 검증과 합법 대상 계산에 모두 적용하며, 향후 맵 효과도 같은 판정을 통과한 `NORMAL` 주사위만 대상으로 삼아야 한다.

### 8.1 주사위 교환

- 내 보드의 `NORMAL` 주사위 하나를 먼저 고르고, 상대 보드의 **같은 라인** `NORMAL` 주사위 하나를 고른다.
- 눈, `id`, `createdBy`를 포함한 주사위 전체를 서로 바꾼다.
- 교환 뒤 점수는 주사위가 새로 놓인 보드의 소유자에게 귀속된다.
- 양쪽에 교환 가능한 `NORMAL` 주사위가 하나 이상 있는 라인만 교환 대상으로 제공한다.
- 어느 한쪽 대상이라도 `SHIELD`면 서버가 `INVALID_ITEM_TARGET`으로 거절한다.

### 8.2 눈 변환

- 내 보드 또는 상대 보드에 이미 놓인 `NORMAL` 주사위 하나를 대상으로 고른다.
- 서버는 현재 눈을 제외한 나머지 다섯 눈 중 하나를 균등하게 선택한다.
- `id`, `NORMAL`, `createdBy`, 보드와 라인은 유지하고 `face`만 변경한다.
- 변환 결과로 일반 배치나 알까기의 합법 대상과 현재 점수가 즉시 달라질 수 있다.
- `SHIELD`는 합법 대상 목록에서 제외하고 직접 명령해도 `INVALID_ITEM_TARGET`으로 거절한다.

### 8.3 실드 강화

- 현재 pending 턴 주사위가 `NORMAL`일 때만 사용할 수 있다.
- `id`, `face`, `createdBy`는 유지하고 `kind`만 `SHIELD`로 변경한다.
- 강화 뒤에도 같은 턴이 유지되며 원하는 내 빈 라인에 착수하거나 타짜·홀드를 선택할 수 있다.
- 실드 주사위는 알까기를 실행할 수 없으므로 강화 즉시 알까기 합법 대상은 사라진다.
- 시작 실드처럼 현재 주사위가 이미 `SHIELD`면 사용 버튼을 비활성화하고 직접 명령도 거절한다.

### 8.4 무작위 투하 (가칭)

- 내 보드와 상대 보드에서 각각 남은 빈 슬롯 전체 중 하나를 균등하게 선택한다. 빈칸이 많은 라인은 그 수만큼 더 높은 확률로 선택된다.
- 선택된 각 보드에 서로 독립적으로 공정한 d6을 굴려 `NORMAL` 주사위를 하나씩 추가한다.
- 라인 안 슬롯 순서는 점수에 영향을 주지 않으므로 선택된 라인의 다음 표시 위치에 넣는다.
- 두 투하 주사위의 `createdBy`는 아이템을 사용한 플레이어이며, 점수 귀속은 실제로 놓인 보드가 결정한다.
- 두 주사위 배치는 하나의 원자적 효과다. 투하 전 양쪽이 14칸이었다면 양쪽 모두 15칸을 채운 상태로 점수를 판정한다.
- 어느 한쪽이라도 투하로 15칸을 채우면 현재 pending 주사위를 더 놓지 않고 즉시 경기를 종료한다. 그렇지 않으면 같은 턴을 계속한다.

### 8.5 주사위 파괴

- 내 보드 또는 상대 보드에 이미 놓인 `NORMAL` 주사위 하나를 대상으로 고른다.
- 선택한 주사위를 해당 라인에서 제거하고 점수를 즉시 다시 계산한다.
- `SHIELD`는 합법 대상에서 제외하며 직접 명령해도 `INVALID_ITEM_TARGET`으로 거절한다.
- 파괴로 홀드한 플레이어의 보드에 빈칸이 생겨도 그 플레이어는 다시 턴을 받지 않는다.

### 8.6 주사위 리롤

- 현재 pending 턴 주사위가 `NORMAL`이고 아이템을 보유했을 때만 사용할 수 있다.
- 서버는 현재 눈을 제외한 나머지 다섯 눈 중 하나를 균등하게 선택한다.
- `id`, `kind`, `createdBy`는 유지하고 `face`만 변경한다.
- 변경된 눈으로 같은 턴에 일반 배치나 알까기·타짜·홀드를 이어서 선택할 수 있다.
- 현재 주사위가 `SHIELD`면 비활성화하고 직접 명령도 `INVALID_ITEM_TARGET`으로 거절한다.

### 8.7 홀수·짝수 주사위

- 현재 pending 턴 주사위가 `NORMAL`일 때만 사용할 수 있다.
- 홀수 아이템은 `1, 3, 5`, 짝수 아이템은 `2, 4, 6` 중 현재 눈을 제외한 후보를 균등하게 선택한다. 따라서 사용에 성공하면 눈은 반드시 달라진다.
- `id`, `kind`, `createdBy`는 유지하고 `face`만 변경한다.
- 변경된 눈으로 같은 턴에 일반 배치나 알까기·타짜·홀드를 이어서 선택할 수 있다.
- 현재 주사위가 `SHIELD`면 두 아이템 모두 비활성화하고 직접 명령도 `INVALID_ITEM_TARGET`으로 거절한다.

## 9. 보상 라인 이벤트

**프로젝트 확장 규칙**

게임마다 라인을 전략적으로 분산할 이유를 만드는 두 개의 독립 보상 목표를 둔다.

1. 게임 생성 시 서버가 세 라인 중 하나를 같은 확률로 `reward lane`으로 정하고 양쪽에 공개한다.
2. `주사위 3개 선점`과 `라인 점수 15점 선점`을 각각 별도 목표로 공개한다.
3. 각 목표를 먼저 달성할 때마다 서버가 `ITEM_TYPES` 여덟 종류 중 하나를 같은 확률로 뽑아 달성 플레이어의 인벤토리에 1개 더한다.
4. 각 목표는 최초 달성자 한 명에게 한 번만 지급한다. 같은 플레이어가 두 목표를 모두 달성하면 아이템을 두 개 받을 수 있다.

3개 목표의 진행도는 해당 플레이어 보드의 실제 주사위 수로 계산한다. `NORMAL`과 `SHIELD`, 주사위의 `createdBy`를 구분하지 않으며 다음 세 배치 경로를 모두 판정한다.

- 일반 착수 `PLACE_OWN`
- 어느 쪽 보드에도 놓을 수 있는 `PLACE_BONUS_SHIELD`
- 양쪽에 하나씩 추가하는 `USE_DROP_ITEM`

15점 목표는 같은 문서의 `scoreLane` 공식을 그대로 사용한다. 일반 착수·보너스 실드·무작위 투하뿐 아니라 보상 라인의 점수를 바꿀 수 있는 주사위 교환과 눈 변환 뒤에도 판정한다. 행동한 플레이어가 아니라 실제 보드 소유자가 달성자다.

실드는 맵 효과로 변경되거나 제거되는 대상이 아니지만 개수와 점수에는 일반 주사위와 동일하게 포함되므로 면역 규칙과 충돌하지 않는다. 상대 보드에 보너스 실드를 놓아 그 보드가 목표를 달성했다면 실제 보드 소유자인 상대가 보상을 받는다.

무작위 투하는 양쪽 배치를 하나의 원자적 효과로 처리한다. 한 번의 투하로 양쪽이 같은 목표를 동시에 달성하면 서버가 두 플레이어 중 한 명을 같은 확률로 선택하고, 그 목표의 보상을 한 명에게만 지급한다. 보상 판정은 15칸 게임 종료 판정보다 먼저 실행해 마지막 배치와 보상 이벤트를 모두 기록한다.

보상 지급 자체는 아이템 사용이 아니므로 `itemUsedThisTurn`을 바꾸지 않는다. 다만 보상을 만든 행동이 무작위 투하라면 그 행동으로 이미 이번 턴 아이템을 사용했으므로 새 아이템도 같은 턴에는 다시 사용할 수 없다.

## 10. 홀드와 항복

### 10.1 홀드

홀드는 현재 점수로 멈추는 전략 행동이며 패배 선언이 아니다.

**원작 확인**

- 현재 들고 있는 주사위와 타짜 후보를 버린다.
- 이후 자신의 모든 턴을 영구적으로 포기한다.
- 상대는 행동 가능한 동안 계속 플레이한다.
- 홀드한 보드의 빈칸은 자동으로 채우지 않는다.

**PVP 규칙 — 인간 대전 확장**

- 홀드한 플레이어의 일반 주사위도 상대가 계속 알까기할 수 있다.
- 알까기 보너스 실드도 홀드한 플레이어의 빈칸에 놓을 수 있다.
- 홀드한 보드에 빈칸이 새로 생겨도 그 플레이어는 복귀하지 않는다.
- 양쪽이 모두 홀드하면 즉시 현재 보드로 승패를 판정한다.

홀드는 일반 입력 단계와 타짜 선택 단계에서만 허용한다. 알까기 보너스 실드 배치 단계는 이미 공격 결과가 발생했으므로 먼저 실드 배치를 완료해야 한다.

### 10.2 항복

**PVP 규칙**

- 항복은 활성 게임의 어느 입력 단계에서나 가능하다.
- 항복 즉시 상대가 승리하며 점수 판정을 실행하지 않는다.
- 결과에는 `reason: SURRENDER`와 항복한 플레이어를 기록한다.

UI는 홀드와 항복을 서로 다른 위치와 문구로 보여주고 각각 확인을 받아야 한다.

## 11. 게임 종료와 승패

### 11.1 정상 종료

다음 조건 중 하나를 만족하면 정상 종료한다.

```text
completed(player) = player.board의 주사위 수 == 15
gameOver = completed(PLAYER_A)
        || completed(PLAYER_B)
        || (!eligible(PLAYER_A) && !eligible(PLAYER_B))
```

턴을 끝내는 배치가 확정되면 다음 행동자를 찾기 전에 `completed`를 먼저 검사한다. 따라서 일반 착수뿐 아니라 알까기 보너스 실드로 자신의 15번째 칸을 채운 경우에도 즉시 종료한다.

이 조건으로 다음 상황을 모두 처리한다.

- 어느 한쪽이 먼저 15칸을 채움
- 한쪽 홀드, 다른 쪽 보드가 가득 참
- 양쪽 홀드

### 11.2 점수 판정

**원작 확인**

1. 같은 인덱스의 세 라인 점수를 각각 비교한다.
2. 더 많은 라인을 이긴 플레이어가 승리한다.
3. 라인 승수가 같으면 세 라인 총점을 비교한다.
4. 총점도 같으면 무승부다.

예를 들어 A의 라인 점수가 `[20, 7, 10]`, B가 `[18, 12, 10]`이면 각자 한 라인을 이기고 한 라인은 비긴다. 총점 `37:40`이므로 B가 승리한다. B가 `[18, 9, 10]`이라면 라인 승수와 총점 `37:37`이 모두 같아 무승부다.

항복이나 연결 만료로 끝난 게임은 이 점수 판정보다 즉시 승리 결과를 우선한다.

## 12. 규칙 상태 머신

```text
WAITING_FOR_PLAYERS
  → READY
  → TURN_ACTION
       ├─ USE_TAZZA → TAZZA_CHOICE
       │                  ├─ CHOOSE_TAZZA_DIE → TURN_ACTION
       │                  └─ HOLD → TURN_END
       ├─ USE_SWAP_ITEM → CHECK_LINE_OBJECTIVES ─┐
       ├─ USE_REROLL_ITEM → CHECK_LINE_OBJECTIVES┤ → TURN_ACTION 유지
       ├─ USE_SHIELD_ITEM ──────────────────┤
       ├─ USE_DESTROY_ITEM ─────────────────┤
       ├─ USE_TURN_REROLL_ITEM ─────────────┤
       ├─ USE_PARITY_ITEM ──────────────────┤
       ├─ USE_DROP_ITEM → CHECK_LINE_OBJECTIVES ─┘ (15칸 완성 시 FINISHED)
       ├─ PLACE_OWN → CHECK_LINE_OBJECTIVES → TURN_END
       ├─ ALKKAGI → BONUS_PLACEMENT
       │                 └─ PLACE_BONUS_SHIELD → CHECK_LINE_OBJECTIVES → TURN_END
       ├─ HOLD → TURN_END
       └─ SURRENDER → FINISHED
  → CHECK_BOARD_COMPLETE
       ├─ 한쪽 15칸 완성 → FINISHED
       └─ 미완성 → NEXT_ELIGIBLE_PLAYER 또는 FINISHED
```

`ROLL`은 클라이언트 명령이 아니다. 서버가 게임 시작, 턴 시작, 알까기 해결 중에 실행하고 결과를 이벤트로 알린다.

## 13. 필수 불변식

규칙 엔진은 모든 명령 전후에 다음을 만족해야 한다.

- 각 라인의 주사위 수는 0~5개다.
- 한 게임 안에서 주사위 `id`는 중복되지 않는다.
- 같은 주사위가 보드와 pending 상태에 동시에 존재하지 않는다.
- `TURN_ACTION`에는 현재 주사위가 정확히 하나 있다.
- `TAZZA_CHOICE`에는 서로 다른 두 눈의 후보가 있고, 실제 주사위 종류는 하나다.
- `BONUS_PLACEMENT`의 pending 주사위는 반드시 `SHIELD`다.
- 모든 `SHIELD` 주사위는 교환·눈 변환·파괴·주사위 리롤·홀짝 변경 아이템과 맵 효과의 대상에서 제외된다.
- 무작위 투하는 양쪽 보드에 정확히 한 개씩 적용된 뒤 종료 여부를 판정한다.
- 홀드한 플레이어는 다음 행동자로 선택되지 않는다.
- 활성 경기에서는 어느 플레이어의 보드도 15개일 수 없다. 15번째 배치와 같은 전이에서 `FINISHED`가 되어야 한다.
- 각 아이템 수량은 0 이상의 정수이며, 한 턴에 성공한 아이템 명령은 최대 하나다.
- 보상 라인은 유효한 라인 하나와 개수 기준 3, 점수 기준 15를 가지며 각 목표의 획득 플레이어와 아이템은 둘 다 비어 있거나 둘 다 유효해야 한다.
- 개수와 점수 보상 이벤트는 각각 경기당 최대 한 번이며, 획득 아이템은 8종 카탈로그 중 하나다.
- `FINISHED` 이후 게임 보드를 바꾸는 명령은 모두 거절한다.
- 파생 점수와 저장된 결과가 현재 보드로 다시 계산한 값과 일치한다.

## 15. MVP 제외 및 미확정 항목

원작의 `티카투카 선언`은 보드 규칙이 아니라 이벤트 포인트의 베팅 배율 기능이다. 커뮤니티 자료에서는 양쪽이 각 한 번 선언할 때마다 2배, 끝까지 진행할 때 추가 2배가 붙어 최대 8배가 된다고 설명한다.

다음은 공개 자료만으로 확정하지 못했다.

- 선언 가능한 정확한 마지막 시점
- 홀드가 끝까지 진행한 배율에 미치는 영향
- 인간 PVP에서 영구 포인트를 정산할 기준

방 코드 친선전에는 영구 포인트가 없으므로 MVP에서는 선언과 베팅을 모두 제외한다. 계정·랭킹·랜덤 매칭·관전·채팅도 현재 규칙 범위에 포함하지 않는다.
